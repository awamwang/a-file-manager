# 应用内「帮助与导引」体系

AFM 此前没有任何面向用户的帮助：`docs/` 全是开发者文档，侧栏与路由无 Help 入口，应用内 `help` 一词零命中。同时 `guide.*` / `NavigatorGuide.vue` 的 “Guide” 已被「此电脑」起始页占用，`Kernel`、`ADR 0016` 等开发者词泄漏进用户文案。

决定建立一套**应用内**帮助体系，分三层：帮助文档（静态查阅）/ 上手提示（首次进入或点「?」的短说明）/ 引导教学（聚光灯式点选教学）。三层共用一份声明式导引注册表，供新特性按同一契约接入。关键取舍：

- **单一注册表为唯一契约**：每条记录绑定视图、文档、文案 key 与教学步骤；`check-i18n` 扩展为校验注册表 key 五语齐全；CONTRIBUTING/PR 模板增加「新特性须登记」勾选项。选它而非各处硬编码，是为了让"上新特性用同一体系"成为结构性约束而非自觉。
- **构建期把 Markdown 内嵌前端**（Vite `?raw`/`import.meta.glob`），不走 IPC、不改 Rust；`docs/` 仅作内容源。这是一种 Tauri 离线桌面应用，内嵌可用零延迟、无运行时文件缺失分支。
- **教学用 `data-tour-id` 稳定锚点 + 聚光灯**：关键步骤须真实点击锚点才推进；锚点缺失或适用条件不满足则跳过该步/不注册该教学，绝不阻塞。不采用强制模态向导。
- **不建独立文档站**：文档与应用同仓、同版本发布。
- **文案改造以去术语化、改 value 不改 key 为主**，以保住五语对齐；确需新 key 时一次补齐五语真译文，不拿英文兜底。

## Consequences

- 新增教学元素必须打 `data-tour-id`，且该 id 一旦发布即视为稳定标识，改名需同步注册表。
- AI 专属教学随 `VITE_AFM_AI_ADDON` 构建风味注册；平台用词（Finder/Trash/⌘）走既有 `platformTerms` 覆盖层，教学文案复用与界面相同的 i18n key，不硬编码按钮名。
- 「?」中枢的「重置上手进度」只清教学已看标记，绝不动用户数据或设置；重播不改进度。
- Guide 一词继续专属于起始页，教学一律称「引导教学 / Guided Tour」，避免与起始页混淆。
- 功能页「?」深链会先导航到该功能所在视图、等首个锚点出现再开教学；等待有 3s 上界，超时或路由不符时**只放弃本次待启动**（不 `stopTour()`），以免误停正在播放的其它教学（如首次启动 quickstart）。
