# Navigator drill-through: flatten subfolders into one list

A Navigator tab shows exactly one directory level. Users who want "the files under this folder *and* its subfolders" had to type a keyword into the in-folder search or walk the tree by hand; Windows Explorer offers no equivalent either, but the need is real (audit every file under a tree, batch file operations on it). AFM therefore gains **drill-through**: a display mode of the Explorer that flattens the subfolders of the current directory into the same list, up to a user-adjustable depth, and rewrites the path displays around it.

1. **A mode, not a page.** The left sidenav is unchanged (`check-nav-ia.mjs` keeps pinning the IA). The entry point is one "icon + chevron" popover in the Navigator toolbar — same shape as *Sort by* / *View* / *Group by* — listing "Off" and the depth levels 1..5 as a single-choice menu. The glyph is an AFM-drawn SVG (`svgOnly`); Segoe has no matching symbol. It shows a **directory tree above one flat row** — the tree being flattened into a list. It carries no arrow: at 16 px an arrow between the two halves collapses into a blob and reads as "download" rather than "flatten" (the first version of this glyph was three indented bars and read as neither).
2. **Two path concepts, deliberately kept apart.** The **drill root** is the directory that was flattened: the start of the tree, and it never moves. The **current path** is what the breadcrumb and the address bar show. Double-clicking a subfolder row only moves the current path — the list keeps showing the whole tree, so the user gets a tree overview plus the ability to jump inside it. Navigating out of the tree (a different directory, a provider, the recycle bin, the guide) turns drill-through off.
3. **Depth semantics.** Depth N flattens N levels of subfolders: depth 1 is the root's own files plus the files inside its direct subfolders, depth 0 means off. Range 0..5, default 2. The **level** is a persisted preference (`core.navigatorDrillDepth`, settings schema v18); the **switch** is session state per pane and is never persisted, so a restart never silently flattens the list.
4. **A dedicated backend command.** `navigator_drill_list(path, depth, show_hidden, limit)` walks with `walkdir`. `navigator_search` is left untouched: its "an empty query does not walk" rule is the search box's existing contract. Drill-through and search are mutually exclusive — a non-empty search wins.
5. **The row cap is request-driven, not a hard cut.** `limit` (default 2000, hard ceiling 20000) is the number of rows one request may return; the walk stops when it has that many and reports `limit_reached`. The visit budget follows the limit (`max(20000, limit × 2)`, hard ceiling 100000) because boundary folders are visited but produce no row. The frontend raises the limit progressively — "load more" doubles it — so a big tree can be shown in full instead of being cut at an arbitrary point of the filesystem walk.
6. **Not paging.** Sorting lives in the frontend (`navigatorSort.ts`), so a backend-paged result would be sorted per page and "page 2" would no longer be "rows 501–1000 of the sorted list". Drill-through therefore widens the window instead: every request returns the *first N rows of the sorted set*, and N grows on demand. "The first N rows" keeps its meaning at every step.
7. **The applied depth is per pane.** The persisted `core.navigatorDrillDepth` is the *preferred* level for the next activation; each pane remembers the depth it is actually flattened at (`DrillPaneState.depth`). Badge, menu checkmark and the row source read the pane's own depth — two panes may drill at different levels at the same time, and the UI must never claim a level a pane is not running at.
8. **Sorting is reused.** The existing *Sort by* menu and its four fields stay; only the "name" comparison switches to the root-relative path, which is identical to the file name in an ordinary listing. Drill rows carry that relative path.
9. **Writes land in the drill root.** New folder / new file / paste always target the drill root and the prompt states the target: a selected row in a flattened list is not a write target, and silently writing into a nested folder would be the worst possible outcome. Rename / delete / cut keep addressing the selected row's own absolute path.
10. **Five path displays change.** The pane path row gets a "Drill N" badge; every row shows its root-relative location (replacing the absolute parent folder that only the search mode showed); the status bar reads "N folders · M files · from K subfolders" (plus the row cap when it bites); the breadcrumb gains a clickable "Drill N" chip (click = off) while the address bar keeps showing the real current path; the tab title gets a "· Drill" suffix.
11. **Drop targets.** A folder row is a valid drop target (the file moves into it); a file row shows no drop hint and refuses the drop; dragging out to other applications is unchanged.
12. **The popover behaves like its neighbours.** Outside click, Escape and the mutual exclusion with *Sort by* / *View* / *Group by* work exactly as they do for those menus.

## Consequences

The toolbar carries one more icon, and "the current folder" now has two readings inside a drilled pane — the drill root and the current path — so every new surface must state which one it shows. A drill load shows a loading banner and surfaces its error with a retry action: a silently failed reload used to leave the previous rows on screen, which read as "the state did not refresh". The settings page hides `core.navigatorDrillDepth` (the toolbar popover is the single entry point, like the sort/group keys). The webdemo mock mirrors the new command, its `limit` argument and the new settings key. Coverage: cargo tests for the depth semantics, the limit behaviour, the caps and the hidden-file rule; `scripts/navigator-drill-checks.ts` for the depth clamp, the per-pane depth isolation, the limit growth curve, the in-tree test, the sort key and the write target; `scripts/check-navigator-drill.mjs` pins the wiring, the five path displays, the menu close semantics and the six-locale strings (`npm run test:navigator-drill`).
