# GUI app 冒烟测试清单（本轮交互改动）

本清单覆盖本轮 `feat/baseline-decisions`（相对基线 `7749fb99`）**只能在真实窗口里点验**
的交互改动：删除/回收判定按文件系统、重命名撞名对话框、从工作组创建项目预览确认、
D5 tasks.json、粘贴目标 / 选中新项 / 滚动排序 / Shift 顺序 / 父子去重，以及 undo 多步
逆序撤销与传输单项失败逐项 Retry/Skip/Abort。

依据 ADR 0025 本仓库**不做 e2e**：这些行为的纯逻辑 / 后端契约已由 cargo（真执行）+
FE `*-checks.ts` + grep 接线 gate 钉住（见
[`external-behavior-baseline-coverage.md`](../external-behavior-baseline-coverage.md)），
但「真实卷 / 真实被锁定文件 / 真实点击弹窗 / 真实窗口滚动」是自动层覆盖不到的，需人工在
窗口逐条点验。每条含 **场景 / 前置（怎么造条件）/ 操作 / 预期**，末尾勾选框供登记。

- 跑法：`npm run tauri:dev`（或已构建的 app），按 SM-01… 顺序执行。
- 全部通过 = 本轮 GUI 行为验收 OK；任一不符 → 记 case id 与现象，回到对应矩阵行
  [`file-ops-scenario-baseline.md`](../file-ops-scenario-baseline.md) Part 3 复核。

## D1 — 回收站判定按文件系统（case DEL-003 / DEL-008）

### SM-01 exFAT / FAT32 U 盘 Delete → 弹永久删除确认（不再静默删）
- 前置：插一个格式化为 **exFAT** 或 **FAT32** 的 U 盘，在其根下建一个测试文件（如
  `E:\smoke.txt`）。该卷无 `$RECYCLE.BIN`。
- 操作：在 Navigator 选中该文件，按 `Delete`（或右键删除）。
- 预期：弹出「**永久删除？**」确认框；确认 → 文件直接消失（永久），**没有**静默秒删、
  也没有报「不能回收」而拒绝；取消 → 文件保留。
- 对照修复前 bug：旧版会把 FAT32/exFAT 误判为可回收 → 经 Shell **静默永久删除、无任何确认**。
- [ ] 通过

### SM-02 NTFS 可移动盘 Delete → 进回收站
- 前置：一个格式化为 **NTFS** 的可移动 U 盘（或第二块 NTFS 分区），建测试文件。
- 操作：选中 → `Delete`。
- 预期：进系统**回收站**（不是永久删除）；回收站里能看到原路径项，可还原。
- [ ] 通过

### SM-03 UNC 网络位置 Delete → 弹永久删除确认
- 前置：在地址栏进入一个 UNC 共享 `\\server\share\...`，内有测试文件。
- 操作：选中 → `Delete`。
- 预期：弹永久删除确认；确认后永久删除（UNC 本就无回收站）。
- [ ] 通过

### SM-04 混合选择（可回收 + 不可回收）一次删除
- 前置：同时选中一个本地 NTFS 文件 + 一个 FAT32/exFAT 文件（或 UNC 文件）。
- 操作：一起 `Delete`。
- 预期：NTFS 项进回收站，不可回收项走**永久删除确认**；各项按能否回收分别处理，部分取消/失败
  不会把已成功项也带崩（回滚已删项）。
- [ ] 通过

## D2 — 重命名撞名走 Replace/Skip 对话框（case NM-002）

### SM-05 重命名成已存在文件名 → Replace / Skip 对话框
- 前置：同一目录下有 `a.txt` 与 `b.txt`（内容不同）。
- 操作：选中 `a.txt`，`F2` 改成 `b.txt` 回车提交。
- 预期：弹出 **替换 / 跳过**（复用粘贴 name-conflict 对话框），**不会**自动改成 `a - Copy`，
  也不会直接报 "already exists" 红字失败。
- [ ] 通过

### SM-06 Replace → 覆盖目标文件
- 前置：同 SM-05。
- 操作：在 SM-05 的对话框点「替换」。
- 预期：`a.txt` 内容覆盖到 `b.txt`（`b.txt` 变成原 a 的内容），源 `a.txt` 消失。
- [ ] 通过

### SM-07 Replace 目标为目录 → 拒绝
- 前置：同目录有文件 `c.txt` 与子目录 `sub/`。
- 操作：把 `c.txt` 重命名为 `sub` 回车 → 选「替换」。
- 预期：**拒绝**覆盖目录（报已存在/失败），`sub/` 仍是目录、内容完好，`c.txt` 保留。
- [ ] 通过

### SM-08 Skip → 取消改名
- 前置：同 SM-05。
- 操作：在 SM-05 对话框点「跳过 / 取消」。
- 预期：改名不发生，`a.txt` 名字与内容都不变，`b.txt` 也不变。
- [ ] 通过

## D4 — 从工作组创建项目：先预览确认（case promote preview）

### SM-09 触发「从工作组创建项目」→ 先弹预览确认
- 前置：已有一个普通工作组（含若干成员标签）。
- 操作：在 WorkGroups 视图「从工作组创建项目」（或在 Projects 视图同义入口）发起。
- 预期：**执行前**先弹 `ConfirmDialog`，文案说明：将创建目标目录 + 生成 `CONTEXT.md` /
  `tasks.json` / skill·MCP 配置，且**原工作组保留**（不是把 WG 改成/提升为项目）。
- [ ] 通过

### SM-10 预览取消 → 不创建任何目录
- 操作：SM-09 弹窗点「取消」。
- 预期：磁盘上**没有**新建项目目录；原工作组仍在；Projects 列表无新增。
- [ ] 通过

### SM-11 预览确认 → 创建成功且原工作组仍在
- 操作：SM-09 弹窗点「确认」。
- 预期：生成项目目录（含 `tasks.json` 等），项目出现在列表；**原工作组仍然存在**且成员不变；
  新项目的成员以工作区链接形式关联。
- [ ] 通过

## D5 — tasks.json 取代 board 任务体系（case project tasks file）

### SM-12 新建项目目录含 tasks.json、无 board.json
- 前置：用「新建项目」创建一个新项目。
- 操作：用资源管理器/AFM 打开该项目目录查看文件清单。
- 预期：有 `tasks.json`（内容为空骨架，例如 `{ "version": 1, "tasks": [] }` 的合法 JSON）、
  `CONTEXT.md`、`project.json`、`members/`；**没有** `board.json`。
- [ ] 通过

### SM-13 ProjectsView 不再有任务看板 / 任务列表 UI
- 操作：打开 Projects 视图并进入任一项目详情。
- 预期：页面**没有**任务四列看板、也没有任务列表/新增任务按钮（task UI 已移除）；任务只作为
  磁盘上的 `tasks.json` 文件存在（供 AI / 手动编辑）。无控制台报错。
- [ ] 通过

### SM-14 旧项目遗留 board.json 被忽略
- 前置：有一个本轮之前创建、目录里残留 `board.json` 的旧项目。
- 操作：在 AFM 里打开该旧项目。
- 预期：项目正常加载、**不**读取 `board.json`（不报错、不渲染旧任务看板）；`board.json` 若存在仅
  作为普通文件出现在目录列表，应用逻辑完全忽略它。
- [ ] 通过

## FE 行为簇 — 粘贴目标 / 选中新项 / 滚动排序 / Shift 顺序 / 父子去重

### SM-15 粘贴目标：选中目录 → 粘入该目录
- 前置：复制 `x.txt`（Ctrl+C）。当前目录另有一个子目录 `dst/`。
- 操作：**单击选中 `dst/`** → Ctrl+V。
- 预期：`x.txt` 被粘进 `dst/` 里面（不是当前目录、也不是 dst 的同级）。
- [ ] 通过

### SM-16 粘贴目标：选中文件 → 粘入其父目录
- 前置：复制 `y.txt`。当前目录内有文件 `z.log`。
- 操作：**单击选中 `z.log`** → Ctrl+V。
- 预期：`y.txt` 粘到 `z.log` 的父目录（= 当前目录），而非「进入 z.log」或报错。
- [ ] 通过

### SM-17 粘贴目标：框选混合 / 无选中 → 粘入当前目录
- 前置：复制若干文件。
- 操作：框选**同时含文件与文件夹的混合**多选后 Ctrl+V；再测「不选中任何项」Ctrl+V。
- 预期：两种情况都粘入**当前目录**（混合选择非单一容器时不钻进任何文件夹）。
- [ ] 通过

### SM-18 复制/移动/粘贴后新项被选中
- 操作：粘贴（含复制粘贴与剪切移动）完成后观察列表选区；再用右键菜单「粘贴」。
- 预期：新写入项被**自动选中**（键盘粘贴与右键粘贴两条路径都要一致），便于直接改名/操作。
- [ ] 通过

### SM-19 Shift 范围按当前排序/视图顺序
- 前置：一列文件，先按「修改日期」或「大小」改变排序（或名称倒序），使视图顺序 ≠ 名称默认顺序。
- 操作：点第 1 行（视图顺序），Shift+点第 4 行。
- 预期：选中的是**当前视图（排序+过滤后）顺序**里的 1→4 行，而不是名称字母序的 1→4；过滤隐藏
  某些项时也只按可见顺序连选。
- [ ] 通过

### SM-20 混选父+子，一次传输只处理一次
- 前置：目录 `A/` 与其子项 `A/sub/`（及更深 `A/sub/deep/`）都可见。
- 操作：同时框选 `A` 和 `A/sub`（父+子都进选区）→ 复制或移动到别处 → 粘贴。
- 预期：目标里 `A` 连同其内部结构**只搬运一次**，不会出现 `A/sub` 被重复处理 / 自我嵌套 / 报错。
- [ ] 通过

### SM-21 操作后滚动位置与排序保持
- 前置：当前目录项目多于屏幕，向下滚动到中部，并把列排序设为非默认（如按大小）。
- 操作：在其中执行一次复制/粘贴（或删除）。
- 预期：操作后列表**仍停在原滚动位置、仍按原排序**，不跳回顶部、不重置排序（区别于切换文件夹
  导航才回顶）。
- [ ] 通过

### SM-22 删除后的选区行为（有意差异）
- 操作：多选后删除其中若干项。
- 预期：AFM **保持现有选区**语义（当前 `delete-keep-selection` 行为），而非 Explorer 的「选邻居」——
  这是有意的产品差异；删除项从列表移除，不报错。
- [ ] 通过

## undo / 错误簇 — 多步逆序撤销 + 传输单项失败逐项处理

### SM-23 连续多次 Ctrl+Z 逆序逐项撤销
- 前置：在同一目录里**依次**执行多步操作（例如：新建 → 复制 → 重命名 → 移动 → 回收站删除）。
- 操作：连按 `Ctrl+Z`。
- 预期：按**逆序（LIFO）逐项**撤销：最后一步先回退，逐次回退到更早的步；每步结果与单独撤销该操作
  一致（不会一次跳过多步、也不会乱序）。
- [ ] 通过

### SM-24 重启后无 undo（不跨会话）
- 前置：做完若干可撤销操作。
- 操作：关闭 AFM 并重新打开，回到该目录按 `Ctrl+Z`。
- 预期：**没有任何跨重启的可撤销项**（undo 栈是内存态、不持久化）；`Ctrl+Z` 静默无操作，不误回退。
- [ ] 通过

### SM-25 传输中单项失败 → 逐项 Retry / Skip / Abort 弹窗
- 前置：批量复制多个文件，其中至少 1 个目标会被**进程锁定 / 权限拒绝 / 目标盘写满**（例如：把一个
  目标文件用另一程序打开占用 → 触发 in-use；或往接近满的盘复制大文件 → disk-full）。
- 操作：发起该多文件传输。
- 预期：失败的那一项弹出**单项**处理框，提供 **重试 / 跳过 / 中止**；选重试再试该项、选跳过继续
  处理其余项（其余项照常完成），不是一失败就整批死掉。
- [ ] 通过

### SM-26 Abort → 回滚本批已完成拷贝，源完好
- 前置：同 SM-25（一批复制，中途某项失败）。
- 操作：在失败项的弹窗选 **中止**。
- 预期：本次批次**已拷贝到目标的部分被清理回滚**（不留半成品）；**源文件全部完好**；剩余未处理项
  不再传输。移动批次按既有决策：已提交的移动不强行搬回（见 coverage ledger R7），重点验源端未损坏。
- [ ] 通过

### SM-27 传输项失败/中止后不污染 undo 栈
- 前置：一批复制中途 Abort 回滚。
- 操作：随后按 `Ctrl+Z`。
- 预期：`Ctrl+Z` 撤销的是上一个**完整**成功的操作，**不会**把刚才中止批次的回滚当成可撤销项；
  目标不出现幽灵半项。
- [ ] 通过
