A File Manager — macOS 首次打开帮助
====================================

这个版本没有使用 Apple Developer ID 签名和公证。macOS 的 Gatekeeper 首次运行时拦截它是正常现象，不代表文件损坏。请只从本项目官方 GitHub Release 下载：
https://github.com/awamwang/a-file-manager/releases

【推荐：通过系统设置允许】
1. 先把 A File Manager.app 拖到“应用程序”(Applications) 文件夹。
2. 双击打开一次。出现“Apple 无法验证…”提示时，点“完成”或“取消”。
   注意：不要点“移到废纸篓”，否则需要重新从安装包里把 App 拖出来。
3. 打开“系统设置” → “隐私与安全性” → 向下滚动到“安全性”。
4. 找到 A File Manager 被阻止的提示，点“仍要打开”，再在弹窗里点“打开”。
5. 之后这个版本就可以正常双击打开。

【如果“仍要打开”按钮没有出现】
打开“终端”(Terminal)，执行下面命令，然后把 Finder 里的 A File Manager.app 直接拖到终端窗口末尾，按回车：

    xattr -dr com.apple.quarantine 

完整例子：

    xattr -dr com.apple.quarantine "/Applications/A File Manager.app"

再双击 App 即可。若下载的是 DMG，也可以先对 DMG 执行同样命令，再挂载安装。

【右键 → 打开】
在部分 macOS 版本上，可以在 Finder 里按住 Control 点按 App（或右键）→“打开”。
但这个入口在 macOS 15/26 对未公证/无 Developer ID 的包可能不显示“打开”按钮，或点了仍被拦。
遇到这种情况请改用上面的“系统设置”或 xattr 方法；这是正常的系统安全策略，不是 App 本身的问题。

【为什么会这样】
macOS 对 Mac App Store 之外分发的软件会检查 Developer ID 签名和 Apple 公证。
只有签名 + 公证的版本才能双击直接打开，不弹这个警告。
当前无证书版本只能做 ad-hoc 签名：它能证明包内文件在构建后没有被改动，但不能替代 Apple 的开发者身份验证。
